# VERITAS-024: AI-Powered Digital Evidence Integrity & Fraud Investigation Platform

VERITAS-024 is an evidence preservation, forensic analysis, and fraud investigation platform built under strict epistemic integrity principles.

## Epistemic Hierarchy
Every piece of information carries exactly one epistemic classification:
- **`VERIFIED_FACT`**: Computed deterministically (SHA-256 hashes, file byte length, raw file headers).
- **`EXTRACTED_OBSERVATION`**: Extracted directly from document content via parsers, OCR, or Gemini Vision. Subject to OCR/reading variance.
- **`TAMPER_INDICATOR`**: Statistical or structural anomalies (Error Level Analysis hotspots, PDF incremental saves, DKIM mismatches). Never treated as absolute proof.
- **`AI_INFERENCE`**: Synthesis, timeline correlations, or narrative explanations generated by Gemini. Marked with required human review warnings.

> **Core Principle**: AI suggests. A human decides. The platform never declares guilt, authenticity, or fraud.

## Setup & Running

### Prerequisites
- Python 3.11+
- Node.js 18+ (tested on Node v24)
- Google Gemini API key (optional; offline fallbacks are fully enabled)

### Backend Setup
```bash
cd backend
python -m pip install -r requirements.txt
cp .env.example .env
# Edit .env with your GOOGLE_API_KEY (optional)
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```
- API Documentation (Swagger): [http://localhost:8000/docs](http://localhost:8000/docs)
- Health Check: [http://localhost:8000/api/health](http://localhost:8000/api/health)

### Frontend Setup
```bash
cd frontend
npm install
npm run dev
```
- Frontend application runs at [http://localhost:3000](http://localhost:3000).

## Demo Script (RF-2291 Investigation)
1. Open the workbench at `http://localhost:3000`.
2. Click **"Load Demo Case"** in the Vault pane to seed the synthetic evidence set:
   - `receipt_refund.pdf`: Refund claim RF-2291 for ₹50,000 on 05 Mar 2026.
   - `receipt_refund_copy.pdf`: Byte-identical duplicate of receipt.
   - `approval_email.eml`: Unsigned internal manager approval on 06 Mar 2026.
   - `chat_export.txt`: WhatsApp export containing conflicting amount (₹45,000).
   - `bank_statement.pdf`: Bank debit on 09 Mar 2026 to "R. Kumar Enterprises".
   - `approval_screenshot.png`: Manipulated screenshot exhibiting compression differences.
3. Review the **Vault Pane** for SHA-256 hashes, exact duplicates, and tamper flags.
4. Open the **Inspector Pane** to examine original extractions, bounding boxes, and ELA heatmaps.
5. Inspect the **Timeline & Relationship Graph** to see entity correlations (e.g., alias matching Ravi Kumar ↔ R. Kumar).
6. Review flagged contradictions in the **Audit Drawer** with deterministic confidence ratings.
7. Accept or reject findings as a human investigator and click **"Verify Audit Chain"** to test cryptographic integrity.
8. Click **"Export Report"** for an HTML print-ready investigation docket.

## Known Limits & Epistemic Boundaries
1. **Error Level Analysis (ELA)**: ELA identifies re-compression anomalies across JPEG matrices. It is a statistical heuristic and may generate false positives on images saved with varied chroma subsampling or progressive scans. It is strictly a `TAMPER_INDICATOR`, not proof of alteration.
2. **OCR & Extraction Variances**: RapidOCR and Vision LLMs can occasionally misread degraded typography or noisy scans. All extracted claims are stamped as `EXTRACTED_OBSERVATION` and cite source bounding boxes for manual verification.
3. **DKIM Verification**: DKIM relies on verifiable public DNS TXT records (`<selector>._domainkey.<domain>`). Mails exported to local EML files or historical emails without live DNS keys will report as `unverifiable` rather than failed.
4. **Autonomous Decisions**: The system will never declare guilt, fraud, or complete authenticity. All final determinations require human sign-off.
